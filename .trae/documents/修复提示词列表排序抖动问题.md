# 解决瀑布流布局导致的重排问题

## 1. 现象解释
- **当前布局**：使用的是 CSS `columns` 属性（报纸排版模式）。
- **排列方式**：它是**先填满第一列**（纵向），再填第二列。
  - 比如 24 个卡片，它会把 1-8 号放在第一列，9-16 号放在第二列...
- **问题根源**：当你加载更多（比如变成 48 个）时，系统为了平衡高度，会重新计算每列应该放多少个。
  - 原本在第二列顶部的 9 号，可能会被挤到第一列的底部（因为第一列现在能容纳更多了）。
  - 这就是为什么你觉得“位置全变了”。

## 2. 解决方案：改为行优先的瀑布流
我们需要一种**“从左到右”**填充的布局（类似俄罗斯方块），这样新加载的数据只会出现在底部，绝不会影响上面。

### 步骤 A：修改 `PromptGrid.tsx`
- 移除 CSS `columns-` 属性。
- 实现一个**手动分列算法**：
  - 根据屏幕宽度决定列数（移动端1列，平板2列，大屏3列）。
  - 将所有提示词按顺序依次分配给各列（1号给列1，2号给列2，3号给列3...）。
  - 渲染为 Flex 布局的多列结构。

这样，1号永远在左上角，2号永远在中上角，3号永远在右上角。加载更多时，新数据只会乖乖排在最下面。
